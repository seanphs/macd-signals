# MACD Signals web version: build spec

This is the contract every file in this repository is built to. The repository is pushed to
GitHub as a public repo (working name `macd-signals`) and published with GitHub Pages. A nightly
GitHub Actions job fetches daily prices for a fixed universe of ~800 tickers, computes MACD / RSI
and the three-stage peak/valley signals in Python, and deploys the static page together with the
computed data. The page does everything else in the viewer's browser: each person keeps their own
holdings/watch lists there and in the URL. No server, no logins, no cost, no Python for viewers.

The math and the signal definitions are **exactly** those of `D:\MACD_Alerts\macd_scan.py`
(verified against the user's broker chart). The look and the Dashboard / Charts / Info structure
follow `D:\MACD_Alerts\make_dashboard.py` (its CSS tokens, sections and glossary text), adapted for
a page that has a full year of history from day one instead of one report day per morning.

Nothing on the page gives buy/sell advice. The owner is new to investing and not a developer; the
README and SETUP must be written for that reader.

## Repository layout

```
.github/workflows/update.yml   nightly fetch + deploy to GitHub Pages (+ keepalive commit)
.github/last-run.txt           one line, the date of the last successful run (keepalive commit target)
fetch_data.py                  standard-library Python; fetches, computes, writes site/data/
universe.txt                   tickers fetched nightly; owner edits this to add tickers
site/index.html                the page (vanilla HTML, no build step, no CDN)
site/app.js
site/style.css
site/data/                     GENERATED by fetch_data.py; gitignored; index.json + one file per ticker
README.md                      what it is, how it works, how to change tickers, troubleshooting
SETUP.md                       step-by-step: account, repo, upload, Pages source, first run, bookmark
.gitignore                     site/data/, __pycache__/
docs/SPEC.md                   this file
```

Paths in the page are relative (`data/index.json`), because GitHub Pages serves a project site
under `https://<user>.github.io/<repo>/`. Local testing: `python -m http.server 8000` from `site/`
(opening `index.html` with file:// does not work: browsers block fetch there).

## fetch_data.py

```
python -I fetch_data.py [--universe universe.txt] [--out site/data] [--only T1,T2,...]
                        [--limit N] [--sleep 0.25] [--range 1y]
```

- Reads `universe.txt`: one ticker per line; `#` starts a comment; blank lines and `[section]`
  headers are ignored. Tickers are upper-cased, `.` becomes `-` (Yahoo uses `BRK-B`), duplicates
  dropped, order kept. Accepted symbol pattern: `^[A-Z0-9^=.-]{1,12}$` after normalisation (the
  `^` prefix is for indexes such as `^GSPC`). Anything else is reported under `failed` with reason
  `bad symbol`.
- `--only` restricts to the listed tickers (testing). `--limit N` takes the first N.
- Fetch: `https://query1.finance.yahoo.com/v8/finance/chart/<urlencoded sym>?range=1y&interval=1d`
  with header `User-Agent: Mozilla/5.0`, 20 s socket timeout. Up to 3 attempts with 2 s, 4 s
  backoff; on HTTP 429 wait 15 s before the next attempt; HTTP 404 is not retried; a non-JSON
  reply (block page) is reported as "Yahoo did not return data (blocked or unavailable)".
  Sequential requests with `--sleep` seconds between tickers.
- Outage cutoff, so a night when Yahoo is down still ends with index.json and the summary line:
  after `TROUBLE_LIMIT` (10) outage-like failures in a row (network errors, HTTP other than 404,
  block pages), every remaining ticker gets one attempt with a `HURRY_TIMEOUT` (10 s) socket
  timeout; the counter resets on any success. After `TIME_BUDGET` (40 min) nothing more is
  fetched and the leftovers go through the stale/failed path with the reason
  "not fetched: the run was out of time". One log line announces each cutoff.
- Drop the current session's partial bar exactly as macd_scan.py does (`currentTradingPeriod.regular`
  check), drop bars whose close is null, convert timestamps to exchange-local dates with
  `meta.gmtoffset`.
- Name: `meta.shortName` or `meta.longName`, else the symbol. Also keep `meta.currency`,
  `meta.exchangeName`.
- Compute, using functions copied verbatim from macd_scan.py (same EMA seeding: SMA of the first n
  values; 12/26/9; RSI 14 Wilder with SMA seed): full series of `macd`, `signal`, `hist`, `rsi`
  aligned with `dates` (`null` during warm-up: first 33 bars for the MACD trio, first 14 for RSI),
  and per-day signal events by running macd_scan's `detect()` on every prefix of the series that has
  at least 4 values. Round closes and MACD values to 4 decimals, RSI to 2.
- Fallback: if a fetch fails and `<out>/<SYM>.json` already exists (restored from the Actions
  cache), keep that file untouched and mark the ticker `stale` in index.json with the error text.
  Otherwise record it under `failed`. Never write a partial file.
- Exit code 0 normally. Exit 1 if fewer than half of the universe ended up with a usable file
  (fresh or cached), so a broken night fails visibly instead of publishing an empty site, or if
  universe.txt is missing or empty. A `--only` run always exits 0.
- Prints one progress line per 50 tickers and a final summary:
  `fetched N  stale M  failed K  last_bar YYYY-MM-DD  elapsed Ss`.
- Python 3.9+, standard library only, no network other than Yahoo.

### site/data/<SYM>.json

```json
{"symbol": "AAPL", "name": "Apple Inc.", "currency": "USD", "exchange": "NMS",
 "fetched": "2026-10-30T02:41:07Z", "stale": false,
 "dates":  ["2025-10-30", "..."],
 "close":  [271.4, "..."],
 "macd":   [null, "... 33 nulls then numbers"],
 "signal": [null, "..."],
 "hist":   [null, "..."],
 "rsi":    [null, "... 14 nulls then numbers"],
 "events": {"2026-10-28": [{"dir": "PEAK", "stage": 3, "detail": "MACD crossed below signal line"}]}}
```

All six arrays have the same length as `dates` (ascending, completed daily bars, about 250).
`events` has a key only for days with at least one signal; `dir` is `PEAK` or `VALLEY`, `stage`
is 1 (early warning), 2 (MACD turned) or 3 (CONFIRMED crossover), `detail` is macd_scan's text.
A stale file is simply the previous night's file left in place.

### site/data/index.json

```json
{"generated": "2026-10-30T02:45:12Z", "last_bar": "2026-10-29", "count": 812,
 "params": {"fast": 12, "slow": 26, "signal": 9, "rsi": 14, "weak_pct": 0.25},
 "tickers": {"AAPL": {"name": "Apple Inc.", "last_bar": "2026-10-29", "stale": false}},
 "failed": {"XYZ": "HTTP Error 404: Not Found"}}
```

`last_bar` is the most common last date across tickers (so one lagging ticker does not define
it). `tickers` lists every ticker that has a data file, fresh or stale. `params` lets the page
show the settings and compute `weak` (|MACD| / close * 100 < weak_pct) exactly as the scanner.

## universe.txt

Plain text, one ticker per line, `#` comments, grouped under comment headers in this order:
`# Indexes` (^GSPC, ^NDX, ^DJI, ^RUT, ^VIX), `# S&P 500 (from Wikipedia, <date>)`,
`# Nasdaq-100`, `# Dow 30`, `# ETFs` (about 130 of the most traded: broad market, sectors,
bonds and T-bills, international, dividend/income, thematic, commodities, leveraged), `# Other
popular stocks and ADRs` (about 150: large non-index names, popular growth/meme/quantum/space/
nuclear/EV/AI/crypto-linked stocks, big ADRs, recent IPOs), `# Added by the owner` (empty, with
a comment explaining how). Yahoo symbol format (`BRK-B`, `BF-B`). Must contain every ticker in
`D:\MACD_Alerts\watchlist.txt`. Every ticker is validated once against Yahoo when the list is
built; ones Yahoo does not know are left out. Target size 750-900.

## The page (site/)

Vanilla HTML/CSS/JS in three files, no frameworks, no CDN, no external requests other than
same-origin `data/`. Works on GitHub Pages under a sub-path and from `python -m http.server`.
Phone width (375 px) must work: tables scroll horizontally inside their container, no page-level
horizontal scroll, 16 px side gutters. Light and dark themes via the same CSS tokens as
make_dashboard.py (`prefers-color-scheme` plus an optional `data-theme` override).

### State: the viewer's lists

- Two lists, `holdings` and `watch`, of validated tickers.
- Sources in priority order: URL hash `#h=VTR,AAPL&w=SPY,QQQ` (lists as comma-separated, URL-safe
  since tickers match `[A-Z0-9^=.-]`; `^` and `=` percent-encoded), then `localStorage` key
  `macd-lists` (`{"h": [...], "w": [...]}`), then empty.
- Every edit saves to localStorage and rewrites the hash with `history.replaceState` so the
  address bar always holds a shareable link. A "Copy link" button copies the full URL and shows a
  short confirmation. Text near the editor: "Your list is saved in this browser and in the page
  address. Nothing is sent anywhere."
- All localStorage reads/writes are wrapped in try/catch (private windows throw).
- First visit (no lists anywhere): the page opens on the list editor with a two-sentence
  explanation and a "Load an example list" button (a dozen well-known tickers) so a visitor sees
  the dashboard immediately.

### List editor

- A panel (tab "My list", also reachable from an "Edit list" button in the header) with two
  textareas, Holdings and Watch, accepting tickers separated by spaces, commas or newlines, any
  case, `.` or `-` for class shares. Save normalises, de-duplicates (a ticker in both goes to
  holdings only), validates against `index.json`.
- Unknown tickers are kept in the list but shown in an "Not in the data set" line with the exact
  wording: "Not in the data set: XYZ. Ask the site owner to add it to universe.txt." They are
  skipped everywhere else.
- Stale tickers (file older than `last_bar`) show a small "data from <date>" badge wherever the
  ticker appears.

### Data loading

- `fetch('data/index.json', {cache: 'no-cache'})` first. Then every ticker in both lists, as
  `data/<encodeURIComponent(sym)>.json?v=<index.generated>` (cache-busting after a nightly
  update), all requests in parallel with a cap of 8 in flight. A loading state while waiting; a
  clear error state if index.json cannot be loaded ("The data has not been published yet, or the
  nightly job has not run. See SETUP.md.").
- Freshness banner: if `index.generated` is more than 3 days old (4 over a weekend), show "Data
  last updated <date>. The nightly job may have stopped; see the troubleshooting section of
  README.md." Also show failed/stale counts from index.json in the footer.

### Derived values (computed in the browser, same definitions as the scanner)

For ticker T on day index i: `weak = |macd[i]| / close[i] * 100 < params.weak_pct`;
`high = max(close[0..i])` (for the latest day this equals the 1-year closing high, which is what
the scanner reports); `pct_below_high = (1 - close[i]/high) * 100`; signal(s) on day i are
`events[dates[i]]` (none if absent). "Near high, no turn yet": no event on day i, not weak,
pct_below_high <= 2 and rsi >= 65 (choppy money-market funds sit at their high permanently, so
they are excluded).

### Dashboard tab (default when lists exist)

Controls in the header: day picker (a select of trading days, newest first, default `last_bar`,
plus previous/next day buttons; only days that have MACD values, i.e. after warm-up), range
selector 5D / 1M / 3M / 6M / 1Y (5, 21, 63, 126, 250 bars) that sets how much history the
sparklines, recent-signal strips, timeline and charts show, an "Edit list" button, a "Copy
link" button. Range and the last tab are remembered in localStorage.

Sections, in this order, all for the selected day:

1. Stats row: holdings with PEAK signals, holdings with VALLEY signals, watch tickers with
   signals, data as of date.
2. "Holdings: PEAK signals" cards, strongest stage first, then not-weak, then larger |MACD| as a
   % of price. Card: ticker (a button; click or Enter opens its chart), name, close, badges for each stage fired
   (P1/P2/P3 colours as the dashboard), choppy badge if weak, a stage stepper (early -> turned ->
   confirmed), RSI, % below high, MACD/signal/hist numbers, the detail text.
3. "Near highs, no turn yet" (holdings, within 2% of high, RSI >= 65, not choppy), one compact
   line each. Table column headers are buttons (keyboard sortable, `aria-sort` on the sorted one).
4. "Holdings: VALLEY signals" cards (blue family).
5. "All holdings" table, sortable by clicking headers (default: closeness to high): Ticker, Name,
   Signal (badges or "-"), MACD vs signal (above/below, histogram rising/falling), Histogram
   sparkline over the range, Close, RSI, % below 1-yr high, Recent (strip over the range: a
   coloured mark on each day the ticker fired; hover shows which). Choppy rows marked.
6. "Watchlist" table: watch tickers that fired on the selected day, peaks first; a short empty
   message otherwise.
7. "Signal timeline": grid of every listed ticker that fired within the range x the days in the
   range (newest on the right), cells with P1..P3 / V1..V3 codes coloured by stage, hover for the
   detail. Horizontally scrollable.

### Charts tab

A ticker select (holdings first, then watch) and the range selector. One inline SVG chart with
three panels: price (with a dashed 1-year-high line and the close value label), MACD (MACD line
blue, signal line orange, histogram bars green/red, dotted zero line, markers on the MACD line on
days a signal fired, coloured by stage), RSI (line with dotted 30 / 70 guides). Hover shows a
crosshair with date, close, MACD, signal, histogram, RSI. Clicking a ticker anywhere on the
Dashboard tab opens it here.

### Info tab

Port the glossary of make_dashboard.py (The basics, Moving averages and MACD, The signals, The
other numbers, Reading the charts, Things to keep in mind), adjusted for this page: the history
is a full year from the first visit rather than filling in day by day; add a short "About this
site" section: data from Yahoo Finance fetched once a night by a free GitHub job, computed as of
the last completed trading day, your list stays in your browser, not financial advice.

### Footer

"Prices from Yahoo Finance, updated nightly. Data as of <last_bar>, generated <generated>.
<count> tickers; <n> failed, <m> stale tonight. This page describes what an indicator is doing.
It is not financial advice."

### Security and robustness

- Everything inserted into HTML that comes from the viewer (tickers) or from data files (names)
  goes through one `esc()` helper. Tickers are validated with `/^[A-Z0-9^=.-]{1,12}$/` before
  being used in a URL.
- No `eval`, no inline event handlers built from strings, no third-party scripts.
- A ticker file that fails to load (404 for a ticker that is in the list but not in index.json,
  network error) must not break rendering: treat as unknown/unavailable and say so.

## .github/workflows/update.yml

- Name: "Update prices and publish". Triggers: `schedule` cron `30 2 * * 2-6` (02:30 UTC Tuesday
  to Saturday = Monday to Friday evenings in the US, after the daily bar is final) and
  `workflow_dispatch`.
- Permissions: `contents: write` (keepalive commit), `pages: write`, `id-token: write`.
  `concurrency: {group: pages, cancel-in-progress: false}`.
- Job `build` (ubuntu-latest): checkout; setup-python 3.12; restore `site/data` from the Actions
  cache (key `prices-${{ github.run_id }}`, restore-keys `prices-`) so last night's files are
  the fallback; `timeout --kill-after=30s 150m python -I -u fetch_data.py` (job
  `timeout-minutes: 180`; if `timeout` has to stop it, the step removes `site/data/*.tmp`, writes
  "fetch_data.py was stopped after 150 minutes without finishing" to the log and the Summary page,
  and fails); the summary line goes to `$GITHUB_STEP_SUMMARY` with a `::notice`/`::error`
  annotation; save the cache under the new key even when the fetch step failed
  (`if: ${{ !cancelled() }}`); configure-pages;
  upload-pages-artifact with `path: site`; keepalive step: write today's date to
  `.github/last-run.txt`, commit as `github-actions[bot]` and push only if it changed (scheduled
  workflows on public repos are disabled after 60 days without repository activity; this commit
  is the activity).
- Job `deploy` (needs build, environment `github-pages`, url from the deployment step):
  `actions/deploy-pages`.
- Use current major versions of the official actions and verify them against the GitHub docs /
  marketplace at build time; pin by major tag (`@v4` style).

## README.md and SETUP.md

Written for a non-developer who owns the repo. README: what the site is, how the nightly job
works, how to add tickers (edit `universe.txt` in the GitHub web editor, commit, optionally run
the workflow by hand), how to share the site, how to read the page (short; the Info tab has the
rest), troubleshooting (Actions tab shows red: open the run, read the summary line; Yahoo
blocked; schedule disabled after inactivity; page shows old data: hard refresh), privacy (lists
stay in viewers' browsers; the share link contains the list; the repo is public but contains no
personal data), not financial advice. SETUP: numbered steps with the exact labels of GitHub's
current UI, verified against docs.github.com at build time: create account, create public repo
named macd-signals with nothing in it, get the files in (two options: the assistant pushes from
the PC with git and the owner signs in once in the browser; or Add file -> Upload files with
drag-and-drop, including the .github folder), enable Pages with Source = GitHub Actions, run the
workflow once by hand from the Actions tab, open the site URL, enter tickers, copy the link.

## Verification expected of every builder

- fetch_data.py: run with `--only` on the tickers in `D:\MACD_Alerts\watchlist.txt` into a temp
  dir and compare, for the latest day, `macd`, `signal`, `hist`, `rsi` and the events against
  `D:\MACD_Alerts\reports\2026-10-29.json` (fields `macd`, `signal`, `hist`, `rsi`, `signals`,
  rounded to 3 decimals as that report rounds). They must match exactly. Note: that report's
  latest bar is 2026-10-28; by the time you run, Yahoo may have a newer bar, so compare the
  matching date, not the last element.
- The page: serve `site/` locally with real or fixture data and open it in the browser; check
  the console is clean, the three tabs render, the list editor round-trips through the URL hash
  and localStorage, the numbers for one ticker match its JSON, and the 375 px layout.
- The workflow and docs: every action version and every GitHub UI label verified against the
  current GitHub documentation.
